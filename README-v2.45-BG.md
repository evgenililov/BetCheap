# BetCheap v2.45.1 — поправки и локална проверка

Този пакет е за преглед. Не е публикуван в Netlify и не потвърждава реални текущи коефициенти без операторски API достъп.

## Поправено

- Основните 1xBet коефициенти и шестте клетки в сравнението са истински линкове, които отварят съответния оператор в нов раздел.
- Новият serverless endpoint `operator-link` не приема произволна цел от браузъра. За 1xBet използва конкретния мач само когато официалният API върне същото ID, правилния режим и HTTPS адрес в `1xbet.com` или `www.1xbet.com`. Иначе отваря публичната операторска страница. Cloudbet отваря `https://www.cloudbet.com/en/sports`. Това е обозначено в интерфейса; не се обещава избран мач или попълнен залог.
- Публичните линкове не са affiliate линкове. Съществуващите проверки за специалните affiliate/selection маршрути са запазени. Не е потвърдена партньорска атрибуция.
- Валиден Cloudbet пазар вече не се скрива от празен стар alias. Два конфликтни alias пазара, спрян пазар и противоречащи дублирани 1xBet изходи не се представят като надеждни цени.
- Каталогът приема положителни числови ID и когато API ги връща като низове.
- Смяната на среща/лига обезсилва предишната Cloudbet заявка, включително обработката на грешките ѝ.
- Cloudbet диагностиката сравнява броя грешки с реално проверяваните до три срещи.
- Времето за чакане от клиента е 45s за последователните каталог → турнир → мач → fallback заявки. Ограниченията на плана за Netlify Functions остават отделни; timeout там изисква проверка на хостинга.

## Локално стартиране

Използвай Node.js 22+ и съществуващата директория на проекта. Не е необходим npm install за приложението: няма външни runtime зависимости.

```sh
cd /workspace/BetCheap
npm test
npm run check
npm start
```

Локалният сървър слуша на 127.0.0.1:8888; не го използвай като production сървър. Поддържа статичните страници и GET Netlify functions. Не симулира доверен Netlify GEO контекст; специалните affiliate маршрути остават затворени локално. Тестовите коефициенти се използват само от браузърния тест и никога от приложението.

Допълнителна браузърна проверка при инсталирани `playwright-core` и Chromium:

```sh
node scripts/browser-smoke.js
```

При различен път за Chromium задай `CHROMIUM_PATH`. За външно инсталиран playwright-core задай `NODE_PATH` към съответната node_modules директория.

## Реални данни: оставаща задължителна проверка

В текущата среда няма `ONEXBET_CLIENT_ID`, `ONEXBET_CLIENT_SECRET`, `ONEXBET_REF` и `CLOUDBET_API_KEY`. Те се задават защитено в настройките на runtime/Netlify, а не в JavaScript, ZIP или чат. За 1xBet запази и предоставените от оператора `ONEXBET_GR`/`ONEXBET_CNT`, ако са необходими за съответния акаунт.

Необходими API дестинации: `cpservm.com` (1xBet OAuth/Marketing) и `sports-api.cloudbet.com` (Cloudbet). Не е нужен API ключ за публичните изходящи операторски линкове.

След конфигуриране провери:

1. `/.netlify/functions/onexbet?op=status`, после `op=catalog-test`.
2. `/.netlify/functions/cloudbet?op=status`, после `op=probe`.
3. Реален общ предстоящ футболен мач: еднакви отбори, старт, full-time 1X2; и трите изхода от двата оператора.
4. Същата проверка за действителен LIVE мач. Cloudbet affiliate feed може да изостава до 60 секунди; времето на получаване не е време на последна промяна на пазара.
5. Кликването към двата оператора в действителната юрисдикция. Операторът може да ограничава достъпа. Няма потвърден Cloudbet event/selection deeplink.

При липсващ или спрян пазар приложението показва причината и не измисля втори коефициент. Betsson още няма проверена интеграция за сравнение; не се представя като наличен втори/трети оператор.

## Проверено в тази среда

- Node автоматизирани тестове: 9 тестови файла, всички успешни.
- Синтактична проверка на JavaScript файловете.
- Chromium с изрично тестови API отговори: age gate, избор на мач, трите 1X2 изхода, по-висока цена/равенство, шест операторски линка, отваряне на Cloudbet, липсващ втори пазар, LIVE линкове и скриване на старите цени при неуспешен refresh.
- Локален HTTP сървър и отделни проверки на реалните endpoints без credentials: честно състояние „не е конфигурирано“.

Това доказва локалното изпълнение и логиката с фикстури. Не доказва текуща достъпност на операторските feeds, GEO допустимост, production deploy или affiliate атрибуция.

## Външна проверка и публикуване

Потребителят предостави Netlify dashboard адрес `https://app.netlify.com/projects/betcheap/deploys`. Предполагаемият публичен hostname `betcheap.netlify.app` не е потвърден: всички read-only заявки от тази среда бяха блокирани от изходящия proxy с `Tunnel connection failed: 403 Forbidden`. Това не е наблюдаван отговор от самото приложение и не доказва проблем в Netlify или операторския API.

В cloud environment draft са запазени startup инструкции и допълнителни разрешени домейни за проверката/API/операторите. Това не прилага автоматично настройките и не публикува нито средата, нито BetCheap. Прегледът, запазването и Publish на cloud средата са отделни от deploy на сайта.

Този пакет съдържа Netlify Functions: използвай поддържан Git/CLI deploy с пакетиране на functions след изрично решение за публикуване. Само статично качване чрез drag-and-drop не е достатъчно доказателство, че функциите са разгърнати. Провери `onexbet`, `cloudbet` и новата `operator-link` функция в Netlify след deploy. В тази задача не е извършван deploy.


## Потвърдени от потребителя партньорски данни за 1xBet

- Сайт: `https://betcheap.netlify.app/`
- Тип: `DirectLink USD`; валута на партньорската конфигурация: `USD`.
- Окончателен tag: `d_6184138m_97c_1x_5888061`.
- Промокод: `1x_5888061`.
- `site=6184138`, `ad=97` са от предоставените по-рано операторски линкове.

Общият партньорски линк в `assets/config.js` е актуализиран:

```text
https://reffpa.com/L?tag=d_6184138m_97c_1x_5888061&site=6184138&ad=97&r=mainpage
```

За съществуващото динамично партньорско маршрутизиране задай в Netlify Environment Variables следната публична, несекретна стойност:

```text
ONEXBET_PARTNER_LINK=https://reffpa.com/L?tag=d_6184138m_97c_1x_5888061&site=6184138&ad=97
```

Базата е без `r`: кодът добавя целта за конкретния мач от официалния API след проверките си. Не използвай фиксирания Arsenal–Leeds път за всички срещи. Промокодът е метаданна; не се добавя измислен URL параметър за автоматично прилагане.

Тази актуализация записва предоставените идентификатори. Тя не доказва отчитане на комисиони и не включва автоматично специалните affiliate маршрути. Основният сравнителен изглед от v2.45 продължава да използва публичния `operator-link`; само промяна в `assets/config.js` не го превключва към партньорски линкове. Преди включване на affiliate маршрутизиране са необходими съществуващите конфигурационни проверки и проверка на отчитането в операторския панел. USD тук не променя формата на десетичните коефициенти.
